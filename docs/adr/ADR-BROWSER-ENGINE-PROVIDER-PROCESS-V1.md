# ADR: Browser Engine Provider Process Architecture and Anti-Corruption Boundary (v1)

Статус: accepted  
Change: C-BROWSER-ENGINE-PROVIDER-PROCESS-20260901  
Рубеж: M1.2 — Browser engine provider process  

---

## 1. Context and Problem Statement

Milestone M1.1 зафиксировал границу нейтрального контракта (`worldline-browser-contract`) и выбор Chromium/CEF на основе прямых измерений ([ADR-BROWSER-ENGINE-V1](ADR-BROWSER-ENGINE-V1.md)). Однако спайк M1.1 управлял браузером снаружи через CDP WebSocket, запускал один процесс и не решал задач промышленного провайдера:
1. Запуск CEF в качестве штатного изолированного нативного процесса плагина Worldline за стандартным протоколом IPC (`worldline-plugin-protocol`).
2. Гарантированное каскадное завершение дерева дочерних процессов Chromium (renderers, GPU, network, utility, crashpad) при аварийном завершении (`hard-kill`) управляющего процесса или сбое хоста.
3. Сохранение и безопасное восстановление ревизий страниц (`DocumentRevision`) с предотвращением повторного использования устаревших ссылок (`ElementRef`).
4. Потокобезопасная интеграция CEF UI Message Loop с асинхронным циклом IPC без блокировок ядра и без дедлоков.
5. Предоставление низкоуровневых примитивов движка (куки, хранилище, синхронные разрешения, перехват загрузок) для будущих сервисных плагинов M1.3 без внесения продуктовой политики в адаптер движка.
6. Выгрузка скриншотов/артефактов в контентно-адресуемое хранилище блобов (`BlobStore`) хоста через обобщенный протокол IPC без утечки путей файловой системы.

## 2. Process Topology and Anti-Corruption Boundary

Архитектура процесса провайдера строго изолирует структуры Chromium/CEF от ядра и внешних контрактов Worldline:

```text
       ┌─────────────────────────────────────────────────────────┐
       │             Worldline Host Process (Microkernel)        │
       │  Capability Broker | Trajectory | SQLite State/BlobStore│
       └────────────────────────────┬────────────────────────────┘
                                    │ stdio Native IPC (Envelopes)
       ═════════════════════════════╪═════════════════════════════
         Anti-Corruption Boundary   │ ProcessTreeContainment (Job Object)
       ═════════════════════════════╪═════════════════════════════
                                    ▼
       ┌─────────────────────────────────────────────────────────┐
       │     BrowserEngineProvider Process (Main Plugin Process) │
       │  - stdio IPC Event Loop (Length-prefixed JSON frames)   │
       │  - Core State Machine (ContextId, PageId, CAS Revision) │
       │  - Thread-affine CEF UI Dispatcher & Message Loop       │
       │  - Synchronous Permission Projection & Download Staging │
       └──────────────┬───────────────────────────┬──────────────┘
                      │ Process Spawning          │
                      ▼                           ▼
       ┌───────────────────────────┐ ┌───────────────────────────┐
       │ Renderer Processes (Blink)│ │ GPU / Utility Processes   │
       │ (Sandboxed, per-site)     │ │ (Sandboxed Audio/Network) │
       └───────────────────────────┘ └───────────────────────────┘
```

### 2.1 Инварианты топологии процессов
1. **Единый исполняемый файл:** Бинарник провайдера при запуске первым делом вызывает `cef_execute_process` для обслуживания дочерних ролей (renderer, gpu, utility). Если запущен дочерний процесс CEF, он немедленно переходит в цикл CEF и **никогда** не открывает IPC Worldline, не запрашивает handles и не исполняет код плагина.
2. **Отсутствие привилегий у дочерних процессов:** Дочерние процессы CEF не являются акторами Worldline, не получают `PrincipalId` / `RuntimeId`, не имеют доступа к дескрипторам хоста и не сохраняют состояние.
3. **Строгая изоляция типов:** Ни одна C/C++ структура, enum, указатель (`CefBrowser*`, `HWND`, `CefFrame*`) или внутренний ID процесса/фрейма Chromium не покидает пределы адаптера провайдера. Все внешние взаимодействия производятся через логические типы `worldline-browser-contract`.

## 3. Generic Host Extensions: Process Containment and Blob Protocol

Для обеспечения надежности многопроцессного движка в обобщенный слой хоста (`worldline-native-host` и `worldline-plugin-protocol`) добавлены два независимых от браузера механизма:

### 3.1 Process-Tree Containment
- На Windows супервизор создает анонимный `Job Object` с флагом `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`.
- Дочерний процесс провайдера помещается в Job Object до начала исполнения кода.
- При завершении хоста, падении или явном `kill()` закрытие дескриптора Job гарантирует мгновенное и безусловное уничтожение ядрами ОС всех потомков процесса (включая все рендереры, GPU и crashpad), исключая появление зомби-процессов.

### 3.2 Bounded Blob IPC Protocol
- В `worldline-plugin-protocol` добавлены `MessageKind::BlobRequest` и `MessageKind::BlobResult`.
- Поддерживаются ограниченные операции `BlobPut`, `BlobGet`, `BlobVerify`.
- Передача бинарных данных (скриншоты, артефакты) осуществляется строго квантованными чанками с валидацией `RuntimeId` и аттенюированных дескрипторов вызова, сохраняя инвариант адресации по хешу содержимого (`BlobId`).

## 4. DocumentRevision Generation Protocol and Crash Safety

Для исключения гонок ревизий DOM и confused-deputy атак при навигации и действиях фиксируется строгий протокол генерации ревизий:

```text
[Engine reports navigation commit]
       │
       ▼
[Provider requests CAS generation reservation in Installation State]
       │
       ▼
[Generation reserved: Rev N+1 > Rev N]
       │
       ▼
[Provider binds Engine DOM/AX tree to Rev N+1 and marks Page Ready]
       │
       ▼
[Provider answers Capability RPC & publishes Observation Event]
```

### 4.1 Правила безопасности ревизий:
1. **Упреждающее резервирование:** `DocumentRevision` инкрементируется и фиксируется в персистентном состоянии **до** того, как ревизия или ссылки `ElementRef` возвращаются вызывающему или публикуются в событиях.
2. **Отвержение устаревших ссылок:** Ссылка `ElementRef = (PageId, DocumentRevision, NodeKey)` действительна только в рамках точного совпадения ревизии документа. При любой навигации или восстановлении после сбоя ревизия строго возрастает, делая старые ссылки недействительными с ошибкой `StaleElementReference`.
3. **Безопасность при сбое (Crash Window):** Если движок совершил навигацию, но процесс упал до завершения фиксации ревизии в состоянии, операция помечается как `Incomplete`. При перезапуске провайдер повторно резервирует строго большую ревизию перед переводом страницы в статус `Ready`.

## 5. Security Defaults and Isolation Policy

1. **CEF Sandbox:** Включен по умолчанию во всех сборках.
2. **Запрет сетевой отладки:** Удаленный порт отладки Chrome DevTools по умолчанию отключен.
3. **Белый список схем:** Провайдер разрешает навигацию только по схемам `http://`, `https://` и `about:blank`. Попытки навигации по схемам `file://`, `javascript:`, `chrome://`, `devtools://` или незарегистрированным схемам немедленно отклоняются (`NavigationDenied`).
4. **Изоляция профилей:** Данные постоянных контекстов (`BrowserContextId`) изолированы в собственных подкаталогах директории установки плагина. Идентификаторы профилей являются логическими строками и не раскрывают абсолютные пути хоста. Инкогнито-контексты используют временные пути в памяти/scratch, уничтожаемые при перезапуске.

## 6. Synchronous Permissions and Primitive Contracts

1. **Синхронные разрешения:** Колбэки разрешений CEF требуют немедленного ответа в потоке UI. Провайдер поддерживает локальную проекцию разрешений, наполняемую через Capability RPC `browser.permission`. Если для целевого контекста и источника (origin) правило не задано, провайдер синхронно возвращает отказ (`Denied`), не блокируя цикл ожидания событий (`EVENT BUS IS NOT RPC`).
2. **Примитивы движка для M1.3:** Контракты `browser.engine.cookies/v0.1`, `browser.engine.storage/v0.1`, `browser.engine.download-hook/v0.1` и `browser.capture/v0.1` объявляются экспериментальными версиями 0.1 с раздельными правами на чтение и мутацию, сохраняя стабильность контрактов 1.0.
3. **Безопасность загрузок:** Загрузки направляются в изолированный каталог `staging`, с валидацией имен файлов и предотвращением путевых инъекций (path traversal / UNC / symlinks).

---

## 7. Headful Windowed Acceptance and OSR Deferral

Для первого промышленного провайдера M1.2 реализуется нативный оконный режим (Windowed Native Path) на Windows:
- Минимальное окно управляется провайдером для проверки рендеринга и обработки событий.
- Off-Screen Rendering (OSR) и композиция через `wgpu` вынесены в Milestone M1.4, чтобы не связывать корректность движка с разработкой композитора интерфейса.

---

## 8. Decision Consequences

### Положительные:
- Полная изоляция движка в отдельном процессе с гарантированным завершением всех потомков через Windows Job Objects.
- Сохранение неизменности и обратной совместимости стабильных контрактов Browser Contract v1.0.
- Невозможность интерполяции пользовательских данных в исполняемый JavaScript-код при действиях.
- Надежное восстановление страниц и контекстов после сбоев без утечки ревизий.
- Интеграция с существующим транспортом блобов ядра для безопасной передачи скриншотов.

### Ограничения:
- Первым проверенным окружением является Windows x86_64; для Linux/macOS поддерживаются контрактные и reference тесты без ложных заявлений о верификации CEF до проведения замеров на этих ОС.
- OSR-рендеринг отложен до рубежа M1.4.
